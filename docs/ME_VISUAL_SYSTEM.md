# ME Visual System

## Purpose

This document defines the customer-facing visual system for **ME Branch ERP**.

ME must look like a serious B-end enterprise product used every day by restaurant operations teams. The product UI should be light, clean, dense, realistic, and highly usable.

## Product UI Direction

Actual app pages should use:

- white and light neutral surfaces
- subtle gray borders
- disciplined blue accents
- compact typography
- realistic table and detail layouts
- controlled density

Presentation boards, executive overview boards, or brand pages may use darker visual treatments, including dark navy backgrounds. Actual operational pages should not.

## Core Visual Rules

- App UI should be light, clean, dense, and realistic.
- Presentation boards can use dark navy background when needed.
- Actual app pages should use white/light surfaces, subtle gray borders, and blue accents.
- Avoid too many oversized rounded cards.
- Use tables, tabs, forms, timelines, and sectioned details for B-end realism.
- Use consistent spacing, type, borders, badges, and status colors.

## Customer-ready Prohibitions

Customer-facing operational pages must not show:

- mock labels
- demo labels
- placeholder language
- dev or internal language
- over-decorated SaaS marketing visuals
- randomly colorful cards
- childish visual style
- black wireframe boxes
- huge empty cards that hide the real information

## Typography

- Page title: `24px / 32px / 650`
- Section title: `15px / 22px / 600`
- Body: `13px / 20px`
- Table text: `12–13px`
- Small label: `11px / 16px / uppercase / 0.04em`
- Metadata value: `13px / 500`

### Typography rule

Operational pages should look compact and disciplined, not like marketing pages with oversized hero text.

## Radius, Border, and Shadow

### Radius

- Small control: `6px`
- Button: `8px`
- Panel or card: `10–12px`
- Large shell surface: `12–16px`

### Border

- Default: `1px solid #E2E8F0`
- Strong: `1px solid #CBD5E1`

### Shadow

- Card shadow: `0 1px 2px rgba(15, 23, 42, 0.04)`
- Elevated panel shadow: `0 8px 24px rgba(15, 23, 42, 0.08)`

Most B-end panels should rely on border and background rather than heavy shadows.

## Component Rules

### Sidebar

- light background
- compact hierarchy
- soft active state
- blue indicator for active item
- no large nav cards
- no heavy outline

### Topbar

- compact control bar
- subtle bottom border or flat surface
- chip-like controls
- no oversized boxed form rows

### Buttons

- one clear primary action
- white/gray secondary actions
- compact height
- no oversized pill buttons

### Badges

- subdued
- consistent status meaning
- never dominate the screen

### Tables

- subtle header fill
- border-bottom row separation
- compact operational text
- minimal decoration

### Tabs

- horizontal
- clear active state
- soft blue underline or soft selected surface
- mobile horizontal scroll allowed

### Timeline

- dots, line, event title, time, muted description
- no giant card per event

### Right Rail

- contextual
- list-based sections
- subtle separators
- 2 to 5 useful sections
- no stacked outlined-button look

## Major Page Realism Rule

Real customer-facing major pages should feel closer to:

- branch detail
- customer detail
- employee detail
- candidate detail
- task detail
- approval detail
- order detail
- finance / account detail
- supplier detail
- inventory item detail
- procurement request detail

These pages should use real information structure, not concept-card decoration.

## Final Acceptance Rule

If a page still looks like:

- a landing page
- a demo dashboard
- a wireframe
- a concept board
- a toy SaaS app

then it does not satisfy the ME visual system.
